## Limitations requiring a decision

- Tool-call failure simulation is unavailable through the standard Codex integration. These cases stop in preflight.
- LLM grading can select the stock Codex backend with `--judge-backend codex`. Exact native tool isolation remains unverified and explicitly accepted by the user. Head-to-head comparison is not restored.
- Eval-declared MCP remains blocked in the public runner pending a reviewed standard-host integration. Ordinary native MCP support does not by itself establish compatibility with every upstream test.
- Attachments and recoverable delegated-agent time limits remain unsupported in the adapter.
- Codex cannot hide manual skill invocation while retaining automatic selection for source skills marked `user-invocable: false`. The port preserves automatic selection and discloses manual visibility.
- Source agent tool restrictions are instructions; native enforcement has not been established. Hooks are advisory and require normal client trust.

The current manual-visibility limitation affects 31 source skills. Native per-tool enforcement is unverified for 47 agent profiles. No limitation is silently skipped, scored as passing, or addressed by patching Codex. Further workarounds require user decision. Broader CLI workflow acceptance, the deferred child permission test, and human Codex desktop checks remain open. Earlier experimental results do not certify the standard-host port.

## Standard judge interface investigation

Installed Vally 0.17.0's `LlmClient` contract requires the judge to invoke the supplied verdict tool. Its `supportsWorkspaceDelivery` declaration is valid only when selected evidence files are available read-only and no other tools except that verdict tool are exposed. The official WSL CLI 0.162.1 supports `--output-schema`, but a structured final response alone does not prove those tool and evidence boundaries or satisfy the required tool invocation. A standard-host judge implementation therefore needs independent evidence for that full contract; it cannot simply set the capability flag or reinterpret JSON as an observed tool call. This investigation starts no models and introduces no implementation or fork.

On 2026-10-13 the user approved a gated implementation using official experimental APIs. The model-free probe accepted process-local restriction flags and an ephemeral thread with `view`, `grep`, and `submit_grade`, but its response exposed no complete tool inventory. Official source/config inspection confirms `ToolsToml` has no global native-tool allowlist; `code_mode_only_strict_3p_tools` defers eligible third-party tools through Code Mode, whose model-facing entrypoints remain `exec` and `wait`. An independent Luna audit reached the same conclusion. Exact Vally tool exposure remains unproven, so the approved stop condition was applied before production judge implementation or the native pilot. No Codex patch, user-config mutation, grader substitution, or native model turn occurred. Evidence: `.cache/official-judge-capability-gate-01621.json` and `.cache/official-judge-tool-exposure-audit-01621.md`.
